# eval/dataset

One folder per case:

```
eval/dataset/parle_g_200g/
  front.jpg            # any *.jpg / *.png / *.webp; sorted by name; first = front
  back.jpg
  gold.json
```

`gold.json`:

```json
{
  "context": { "source": "package", "is_imported": false, "pdp_area_cm2": 180, "net_qty_g_or_ml": 200 },
  "declarations": {
    "manufacturer": "Parle Products Pvt Ltd, Vile Parle (East), Mumbai 400057",
    "generic_name": "Biscuits",
    "net_quantity": "200 g",
    "mfg_date": "03/2026",
    "mrp": "MRP ₹20.00 Inclusive of all taxes",
    "consumer_care": "consumercare@parleproducts.com 1800-123-4567"
  },
  "violations": ["D8"]
}
```

- `context` fields are `ScanContext` fields (`worker/pipeline/models.py`). Only what the inspector would know.
- `declarations` use the canonical field names from `CLAUDE.md`. A value is the full printed line, anchor word included (`"MRP ₹20.00 (Inclusive of all taxes)"`, not `"₹20.00"`). Values are matched loosely: case, punctuation, spacing and the currency marker are ignored, so `₹20.00`, `Rs 20.00` and `20.00` are the same value (no PP-OCR dictionary contains a `₹`). A dot between digits is a decimal point and still has to match.
- `synthetic_*` cases are generated by `eval/make_synthetic.py` (clean print, one panel). They are a smoke test, not the benchmark.
- `violations` lists the expected rule codes, excluding `info` rows. `worker/tests/test_dataset.py` checks every gold file: canonical field names, real rule codes, valid context keys, an image present. Run `make test` after adding cases.

## Shot list for the real set (40–60 packs + 5 screenshots)

Photograph the declaration panel straight on, fill the frame, no flash glare. Put a credit card
or a printed ArUco marker (`DICT_4X4_50`) flat next to the panel on at least 15 packs — those are
the only ones that can test the font rules.

| How many | What | Tests |
|---|---|---|
| 15 | Everyday kitchen packs, clean labels, card in frame | D1–D6, D8, F1, F2 |
| 8 | Small sachets and 10 g / 10 ml packs (shampoo, ketchup, spice) | X1 downgrades |
| 6 | Imported goods (olive oil, chocolate, cosmetics) | D7, country of origin |
| 6 | Declarations split across two panels, or printed on a seam / bottom | P1, P3 |
| 5 | Low contrast, glossy, embossed or curved surfaces | P2, unverifiable paths |
| 5 | Packs you believe are non-compliant (no tax wording, "approx", no care email) | D3, D5, D6 |
| 5 | Non-English or bilingual labels | P4 |
| 5 | E-commerce listing screenshots, full page (`source: ecommerce`) | E1, E2 |

Write `gold.json` from the printed pack, not from what the OCR returns. If a declaration is
genuinely absent, leave the field out — do not write an empty string.
